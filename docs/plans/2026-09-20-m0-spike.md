**Goal:** Resolve the four risks in the design's risk register and produce an explicit
go/no-go on the phonetic track, before any application code is written.

## Scope discipline

This is a spike, not a milestone. The temptation to start building the real app here is
the main way M0 fails.

**Do not** set up Vitest, React, routing, state management, or CSS frameworks. **Do not**
build a reusable audio pipeline. M1 introduces real test infrastructure; M0 answers
questions and gets deleted.

Each task's deliverable is a **recorded finding**, not working code.

## Prior research (already done, 2026-09-20)

R1 is substantially de-risked. Confirmed by querying the Hugging Face API:

- **`onnx-community/wav2vec2-lv-60-espeak-cv-ft-ONNX`** — primary candidate.
  `library_name: transformers.js`, `pipeline_tag: automatic-speech-recognition`, correct
  `onnx/` layout with 8 quantizations, ~1200 downloads. ONNX export of
  `facebook/wav2vec2-lv-60-espeak-cv-ft` (245k downloads).
- **Its `vocab.json` is 392 entries of literal IPA** — `ə ɛ ɾ ɪ ð ɹ ʊ ʌ æ aɪ ʃ ɔ ŋ ɚ eɪ oʊ
  θ aʊ`, including the flap and rhotic schwa. The model emits IPA directly; no ARPAbet
  conversion layer is needed on the phonetic track.
- **`onnx-community/wavlm-large-english-phoneme-ONNX`** — fallback. English-specific, same
  transformers.js tagging, near-identical sizes.
- **`robg/speako-phoneme-recognizer`** — second fallback, only ships `model_quantized.onnx`
  at 355 MB.

**New constraint discovered:** every available phoneme model is large-architecture.

| Quantization | espeak model | wavlm model |
| --- | --- | --- |
| fp32 (`model.onnx`) | 1264 MB | 1262 MB |
| fp16 | 632 MB | 632 MB |
| int8 / quantized | 318 MB | — |
| q4 | 242 MB | 241 MB |
| **q4f16** | **197 MB** | **197 MB** |

~197 MB is the floor. Whether q4 quantization degrades phone accuracy enough to matter is
now a measurement task (Task 5), not an assumption.

## Task 2: Audio fixture and decode helper

Every probe needs the same input: a known WAV decoded to 16 kHz mono `Float32Array`
(what both models expect).

**Files:**
- Create: `spike/public/fixture.wav`, `spike/src/audio.ts`

**Step 1: Record the fixture**

Record roughly 8-12 seconds of yourself, 16-bit WAV, reading:

> "I bought a little butter and some water at the city market on Saturday."

This sentence is chosen deliberately: *butter, little, water, city, Saturday* are all
flapping environments, so the phonetic track should show `ɾ` where the phonemic track
shows `/t/`. That contrast is exactly what Task 4 needs to verify, and it is the project's
core demo in miniature.

Save to `spike/public/fixture.wav`. Note the exact sentence in the findings doc.

**Step 2: Write the decode helper**

Create `spike/src/audio.ts`:

```ts
/** Decode an audio file to 16kHz mono Float32Array — the format both models expect. */
export async function decodeTo16kMono(url: string): Promise<Float32Array> {
  const bytes = await (await fetch(url)).arrayBuffer();

  const ctx = new AudioContext();
  const decoded = await ctx.decodeAudioData(bytes);
  await ctx.close();

  // Resample to 16kHz mono by rendering through an OfflineAudioContext.
  const offline = new OfflineAudioContext(1, Math.ceil(decoded.duration * 16000), 16000);
  const src = offline.createBufferSource();
  src.buffer = decoded;
  src.connect(offline.destination);
  src.start();

  return (await offline.startRendering()).getChannelData(0);
}
```

**Step 3: Probe it**

In `spike/src/main.ts`:

```ts
import { report } from './ui';
import { decodeTo16kMono } from './audio';

const audio = await decodeTo16kMono('/fixture.wav');
const seconds = audio.length / 16000;

report('P0 decode', seconds > 1 && peak > 0.01 ? 'pass' : 'fail',
  `${audio.length} samples, ${seconds.toFixed(2)}s, peak ${peak.toFixed(3)}`);
```

**Step 4: Verify**

Reload the page. Expected: PASS, duration matching your recording, peak between roughly

## Task 3: Probe R3 — Whisper and word-level timestamps

**Files:**
- Create: `spike/src/probe-whisper.ts`
- Modify: `spike/src/main.ts`

**Step 1: Write the probe**

```ts
import { pipeline } from '@huggingface/transformers';
import { report } from './ui';

export async function probeWhisper(audio: Float32Array) {
  const t0 = performance.now();
  const asr = await pipeline(
    'automatic-speech-recognition',
    'onnx-community/whisper-base.en',
    { device: 'webgpu', dtype: 'q8' },
  );
  report('R3 load', 'info', `whisper-base.en loaded in ${((performance.now() - t0) / 1000).toFixed(1)}s`);

  const out: any = await asr(audio, { return_timestamps: 'word' });

  const chunks = out.chunks ?? [];
  const timed = chunks.filter((c: any) => Array.isArray(c.timestamp) && c.timestamp[0] != null);

  report('R3 transcribe', out.text?.trim() ? 'pass' : 'fail', out.text ?? '(no text)');
  report('R3 word timestamps', timed.length > 0 ? 'pass' : 'fail',
    timed.length === 0
      ? 'No word-level timestamps — fall back to chunk-level alignment in M3'
      : timed.slice(0, 8).map((c: any) => `${c.text.trim()} [${c.timestamp[0]}-${c.timestamp[1]}]`).join('\n'));

  return out;
}
```

**Step 2: Wire into `main.ts` and reload**

Expected outcomes, all of which are findings rather than failures:
- Transcription roughly matches the fixture sentence (minor errors are fine and expected)
- Either word timestamps appear with plausible times, or they do not — record which

**Step 3: Record the finding**

Note in the findings doc: load time, whether WebGPU was actually used (check the console —
transformers.js logs the backend, and may silently fall back to WASM), and whether word
timestamps worked. **If it silently fell back to WASM, that is itself an important

## Task 4: Probe R1 — the phoneme model (THE GATE)

This is the task the whole spike exists for. If it fails, the design changes.

**Files:**
- Create: `spike/src/probe-phoneme.ts`
- Modify: `spike/src/main.ts`

**Step 1: Write the probe**

```ts
import { pipeline } from '@huggingface/transformers';
import { report } from './ui';

const CANDIDATES = [
  'onnx-community/wav2vec2-lv-60-espeak-cv-ft-ONNX',  // primary — IPA vocab confirmed
  'onnx-community/wavlm-large-english-phoneme-ONNX',  // fallback
];

export async function probePhoneme(audio: Float32Array) {
  for (const model of CANDIDATES) {
    try {
      const t0 = performance.now();
      const rec = await pipeline('automatic-speech-recognition', model, {
        device: 'webgpu',
        dtype: 'q4f16',   // 197MB — the smallest available; Task 5 tests whether it is good enough
      });
      const loadS = ((performance.now() - t0) / 1000).toFixed(1);

      const t1 = performance.now();
      const out: any = await rec(audio);
      const inferS = ((performance.now() - t1) / 1000).toFixed(2);

      const text: string = out.text ?? '';
      // The espeak vocab emits IPA directly. Confirm we see real IPA, not ASCII letters.
      const hasIpa = /[əɛɪʊʌæɹðθŋɾɚ]/u.test(text);

      report(`R1 ${model}`, hasIpa ? 'pass' : 'fail',
        `load ${loadS}s, infer ${inferS}s\noutput: ${text}\n` +
        (hasIpa ? 'Contains IPA symbols.' : 'No IPA symbols found — check vocab/tokenizer decoding.'));

      // The money check: flapping. /t/ between vowels should surface as [ɾ].
      if (hasIpa) {
        report('R1 flapping', text.includes('ɾ') ? 'pass' : 'info',
          text.includes('ɾ')
            ? 'Flap [ɾ] detected — the phonemic/phonetic divergence is real and measurable.'
            : 'No flap detected. Either your dialect does not flap here, or timing/decoding needs review.');
      }

      return { model, text };
    } catch (err) {
      report(`R1 ${model}`, 'fail', String(err));
    }
  }

  report('R1 GATE', 'fail', 'No phoneme model loaded. Phonetic track is not viable — revisit the design.');
  return null;
}
```

**Step 2: Run and observe**

Expect a slow first load — roughly 197 MB over the network. Watch the Network tab to
confirm weights come from `huggingface.co` / `cdn-lfs`, not from your own origin. That
confirms the design's bandwidth strategy.

**Step 3: Interpret the gate**

- **PASS with IPA output** → phonetic track is viable. Proceed.
- **PASS but no IPA symbols** → model loads but decoding is wrong. Inspect
  `tokenizer_config.json` and try decoding token IDs manually against `vocab.json`. Not a
  gate failure; a decoding bug.
- **All candidates FAIL to load** → **gate failure.** Stop. Do not proceed to Task 5.
  Return to the design and adopt the R1 fallback: phonemic-only plus rule-based allophony.

**Step 4: Commit**

```bash
git add spike && git commit -m "Probe R1: phoneme model viability (gate)"
```

## Task 5: Measure the quantization/accuracy tradeoff

Only run this if Task 4 passed. This resolves the constraint discovered during research:
q4f16 is 197 MB but may degrade CTC phone accuracy.

**Files:**
- Modify: `spike/src/probe-phoneme.ts`

**Step 1: Sweep the quantizations**

```ts
export async function sweepQuant(audio: Float32Array, model: string) {
  const results: Record<string, string> = {};

  for (const dtype of ['q4f16', 'q4', 'int8', 'fp16'] as const) {
    try {
      const t0 = performance.now();
      const rec = await pipeline('automatic-speech-recognition', model, { device: 'webgpu', dtype });
      const out: any = await rec(audio);
      results[dtype] = out.text ?? '';
      report(`R1 quant ${dtype}`, 'info',
        `${((performance.now() - t0) / 1000).toFixed(1)}s total\n${out.text}`);
    } catch (err) {
      report(`R1 quant ${dtype}`, 'fail', String(err));
    }
  }

  // fp16 is the closest available proxy for ground truth.
  const ref = results['fp16'];
  if (ref) {
    for (const [dtype, text] of Object.entries(results)) {
      if (dtype === 'fp16') continue;
      report(`R1 drift ${dtype}`, 'info',
        `vs fp16 — identical: ${text === ref}\n  fp16: ${ref}\n  ${dtype}: ${text}`);
    }
  }
  return results;
}
```

**Step 2: Record the decision**

Write down, per quantization: download size, load time, inference time, and how far the
phone string drifted from fp16. Then pick the smallest quantization whose drift is
acceptable, and record the reasoning.

This table belongs in the final README — "here is why the model is 197 MB and not 632 MB"
is a good thing to be able to answer.

**Step 3: Commit**

```bash
git add spike && git commit -m "Measure phoneme model quantization tradeoff"
```

## Task 6: Probe R4 — do we actually need SharedArrayBuffer?

The cheapest possible outcome for the project is discovering we never needed
cross-origin isolation.

**Files:**
- Create: `spike/src/probe-isolation.ts`

**Step 1: Write the probe**

```ts
import { report } from './ui';

export function probeIsolation() {
  report('R4 crossOriginIsolated', 'info', String(self.crossOriginIsolated));
  report('R4 SharedArrayBuffer', 'info',
    typeof SharedArrayBuffer !== 'undefined' ? 'available' : 'NOT available');
  report('R4 WebGPU', (navigator as any).gpu ? 'pass' : 'fail',
    (navigator as any).gpu ? 'navigator.gpu present' : 'No WebGPU — WASM fallback only');
}
```

**Step 2: Run on the plain dev server**

Vite's dev server sets no COOP/COEP by default, so expect `crossOriginIsolated: false`
and `SharedArrayBuffer` unavailable.

**The decisive question:** did Tasks 3-5 pass anyway, under WebGPU, without isolation?

- **Yes** → **R4 resolved cheaply. Drop COOP/COEP from the design entirely, and R2
  evaporates with it.** Skip Task 7. Record this clearly — it removes a whole class of
  deployment complexity.
- **No, models silently fell back to single-threaded WASM and were unusably slow** →
  isolation is needed for WASM threads. Proceed to Task 7.

**Step 3: Commit**

```bash
git add spike && git commit -m "Probe R4: cross-origin isolation requirement"
```

## Exit criteria

M0 is complete when all of the following are true:

1. A findings document exists with an explicit GO or NO-GO on the phonetic track
2. A phoneme model and quantization are chosen, with the size/accuracy reasoning recorded
3. Whether COOP/COEP is needed at all is settled
4. The M1 performance budget is written down as concrete numbers
5. The design document is amended wherever the findings contradict it

**Only then** write the M1 plan. Writing it before this point means planning against
assumptions this spike exists to replace.
